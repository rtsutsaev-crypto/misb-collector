ЕГРЮЛ ДЛЯ «МОНИТОРА-КОНСОЛИДАТОРА МИСБ»: отдельный запуск этапа egrul через API Чекко (чья закупка и дочерние общества). Артефакт: https://claude.ai/artifact/DXESGRPAkHFVVU8Ugj5PUQ. Запуск только вручную, расписания нет. Работай сам, без вопросов пользователю. База сайта — только инструментом ArtifactData (ToolSearch "select:ArtifactData"), url артефакта выше. Ключ Чекко: {CHECKO_KEY}. В базу, журнал и заметки ключ не записывай. Ничего не выдумывай: ИНН, названия, статусы и доли — только из ответов API. Время бери из `date -u +%FT%TZ`. runId = "egrul-" + UTC сейчас в виде ГГГГММДД-ЧЧММСС.

API ЧЕККО. Адрес https://api.checko.ru/v2, ключ параметром key. Запрос: curl -sS -m 30 -o <файл>.json "https://api.checko.ru/v2/company?key=<ключ>&inn=<ИНН>"; ответ разбирай python3 из файла (ответы большие: у крупных компаний сотни связанных организаций). Если shell-запрос к api.checko.ru запрещён — делай тот же запрос через WebFetch с просьбой вернуть нужные поля дословно. Ответ: {data, meta}. meta.status — "ok" или ошибка; meta.today_request_count — запросов за сегодня по этому ключу (бесплатный ключ — около 100 в сутки, общий с основным заданием сбора). Поля data у /company: ИНН, НаимСокр, Статус.Наим, ОКВЭД.Код и ОКВЭД.Наим, СЧР (среднесписочная численность, может быть null), Контакты.Тел, Контакты.Емэйл, Контакты.ВебСайт; Учред — учредители по видам: РосОрг (российские юрлица: ИНН, НаимСокр, Доля.Процент), РФ (государство и субъекты), ИнОрг (иностранные), ФЛ, ПИФ; СвязУчред — организации, где эта компания учредитель (ИНН, НаимСокр, Статус; долей в этом списке нет).

ШАГ 1. ПРОГРЕСС. get egrul/progress. Если status "running" с другим runId и updatedAt моложе 20 минут — идёт другой запуск: ничего не записывай и заверши работу. Иначе set egrul/progress: {runId, status "running", startedAt и updatedAt = сейчас, stage «Проверяю ключ Чекко», counters: {company: 0, search: 0, orgs: 0, linked: 0, candidatesInn: 0, notFound: 0}, log: [{at, text: "Запуск этапа ЕГРЮЛ (Чекко)"}]}. После каждого запроса к API — update egrul/progress: updatedAt, stage, counters, log (последние 40 записей, новые в конец).

ШАГ 2. ДАННЫЕ (get/list с out_dir во временную папку). config/sources-plan → у источника с key "egrul" возьми maxPerRun, maxDepthUp, minShare. meta/holdings → ИНН групп реестра: поле inn у групп и 10–12-значные aliases у групп и дочерних узлов; запомни, какой группе принадлежит каждый ИНН. list ownership (limit 1000). list leadsets (limit 1000) → ИНН заказчиков: поле customerInn или customer вида «ИНН 1234567890»; запомни у каждого ИНН law, source и collectedAt его лидов. meta/egrul-state (нет — nextGroup = 0, nextChild = 0; запомни version). orgdir/group-candidates (запомни version).

ШАГ 3. КЛЮЧ И ЛИМИТ. Контрольный запрос /company по ИНН 7708503727 (ОАО «РЖД»). Ошибка доступа, ограничение по IP, неверный ключ, HTTP 401/403 или meta.status не "ok" — stage «Ключ Чекко не принят: <текст ответа без ключа>», шаг 7 со status "error". meta.today_request_count уже 90 или больше — stage «Лимит Чекко на сегодня исчерпан», шаг 7 со status "error". Бюджет запуска: min(maxPerRun, 90 − today_request_count) запросов; после каждого ответа сверяй today_request_count и останавливайся на 90. В log: «Ключ принят: за сегодня N запросов; бюджет на запуск B». Ответ по РЖД используй в шаге 6, повторно не запрашивай.

ШАГ 4. UPWARD (сначала). ИНН заказчиков лидов, которых ещё нет в ownership и которые не входят в ИНН групп реестра. Порядок заказчиков: сначала заказчики лидов по 223-ФЗ (law "223-ФЗ", source gosplan:fz223 или номер из 11 цифр, начинается с 3) и лидов, где в названии заказчика есть ПАО, АО, ООО, ЗАО или ОАО; затем прочие; заказчики, у которых все лиды по 44-ФЗ, — в последнюю очередь (это обычно бюджетные учреждения и органы власти, в группы они не входят). Внутри каждой очереди — сначала самые свежие по collectedAt. Для каждого, пока есть бюджет: /company?inn=<ИНН>. Учредитель из Учред.РосОрг с ИНН из реестра групп — группа найдена. Иначе поднимись к учредителю из Учред.РосОрг с наибольшей Доля.Процент тем же запросом, не глубже maxDepthUp; если учредители только РФ, ИнОрг, ФЛ или ПИФ — это вершина цепочки. Запиши ownership/<ИНН> (set): {inn, name (НаимСокр), status (Статус.Наим), okved (ОКВЭД.Код + " " + ОКВЭД.Наим), staff (СЧР), contacts: {phone (Тел, через запятую), email (Емэйл, через запятую), site (ВебСайт)}, founders: [{inn, name, share}] (из РосОрг; из РФ и ИнОрг — с тем, что есть в ответе), chain: [{inn, name, share}] (путь вверх от этой компании до группы или до вершины), group (имя группы из реестра или ""), groupShare (доля на первом шаге цепочки), checkedAt: сегодня, via: "checko company"}. Каждый пройденный уровень цепочки тоже запиши в ownership, чтобы не спрашивать повторно. Не найдено (ИП, ошибка «не найдено», пустой data) — запиши {inn, name: "", status: «не найдено в Чекко» или текст ответа, checkedAt: сегодня, via: "checko company"}, counters.notFound + 1.

ШАГ 5. CANDIDATES (если бюджет остался). Кандидаты из orgdir/group-candidates (поле candidates) по возрастанию rank, у которых нет inn: /search?key=<ключ>&by=name&obj=org&query=<название без кавычек и организационно-правовой формы>. Поля ответа определи по нему самому. Если метод недоступен на тарифе — отметь в log и переходи к шагу 6. ИНН бери только при точном совпадении сокращённого наименования, иначе кандидату note «ИНН не определён однозначно». Найден — /company и запись в ownership, как в шаге 4. У кандидата заполни inn, ownerGroup (если цепочка привела в группу реестра), ownerChain, checkedAt; в конце одним update orgdir/group-candidates с if_version (массив candidates целиком; конфликт — перечитай и наложи свои изменения).

ШАГ 6. DOWNWARD (если бюджет остался). Головные компании групп реестра по порядку, начиная с nextGroup (группа без ИНН — пропусти). /company по ИНН головной (для РЖД — ответ из шага 3). Из СвязУчред возьми организации со статусом «Действует», которых ещё нет в ownership, начиная с позиции nextChild. Долей в СвязУчред нет, поэтому для каждой — /company по её ИНН и найди головную в её Учред.РосОрг. Доля.Процент не меньше minShare — запиши в ownership с group = эта группа, chain: [{inn головной, name, share}], groupShare = доля; меньше minShare — запиши с group "" (founders покажут долю). Внучек в этом задании не запрашивай. Бюджет кончился посреди группы — запомни nextChild (позицию в списке действующих); группа пройдена целиком — nextGroup + 1, nextChild = 0. В конце set meta/egrul-state {nextGroup (по модулю числа групп), nextChild, updatedAt} с if_version.

ШАГ 7. ИТОГ. update egrul/progress: status "done" или "error", finishedAt, updatedAt, counters, stage — «Готово: запросов company N, search S; записано организаций M, привязано к группам K, кандидатов с ИНН L; за сутки по ключу R» или текст ошибки. set egrul-runs/<runId>: {runId, startedAt, finishedAt, status, counters, note}. Итоговое сообщение пользователю не нужно.
