ЕГРЮЛ ДЛЯ «МОНИТОРА-КОНСОЛИДАТОРА МИСБ»: отдельный запуск этапа egrul (чья закупка и дочерние общества). Артефакт: https://claude.ai/artifact/DXESGRPAkHFVVU8Ugj5PUQ. Запуск только вручную, расписания нет. Работай сам, без вопросов пользователю. База сайта — только инструментом ArtifactData (ToolSearch "select:ArtifactData"), url артефакта выше. API-ФНС вызывай только через WebFetch; из shell к сайтам не обращайся. Ключ API-ФНС: {EGRUL_KEY}. В базу, журнал и заметки ключ не записывай. Ничего не выдумывай: ИНН, названия, статусы и доли — только из ответов API. Время бери из `date -u +%FT%TZ`. runId = "egrul-" + UTC сейчас в виде ГГГГММДД-ЧЧММСС.

ШАГ 1. ПРОГРЕСС. get egrul/progress. Если status "running" с другим runId и updatedAt моложе 20 минут — идёт другой запуск: ничего не записывай и заверши работу. Иначе set egrul/progress: {runId, status "running", startedAt и updatedAt = сейчас, stage «Проверяю ключ API-ФНС», counters: {egr: 0, search: 0, orgs: 0, linked: 0, candidatesInn: 0, notFound: 0}, log: [{at, text: "Запуск этапа ЕГРЮЛ"}]}. После каждого запроса к API — update egrul/progress: updatedAt, stage, counters, log (последние 40 записей, новые в конец).

ШАГ 2. ДАННЫЕ (get/list с out_dir во временную папку). config/sources-plan → у источника с key "egrul" возьми base, budgetShare, maxPerRun, maxDepthUp, minShare. meta/holdings → ИНН групп реестра: поле inn у групп и 10–12-значные aliases у групп и дочерних узлов; запомни, какой группе принадлежит каждый ИНН. list ownership (limit 1000). list leadsets (limit 1000) → ИНН заказчиков: поле customerInn или customer вида «ИНН 1234567890»; порядок — сначала лиды с самым свежим collectedAt. meta/egrul-state (нет — nextGroup = 0; запомни version). orgdir/group-candidates (запомни version).

ШАГ 3. КЛЮЧ И ЛИМИТ. WebFetch base/stat?key=<ключ> с просьбой вернуть JSON дословно. Возьми лимит и истрачено по методам egr и search. Ошибка ключа, 401 или 403 — stage «Ключ API-ФНС не принят: <текст ответа без ключа>», шаг 7 со status "error". Остаток egr равен 0 — stage «Лимит API-ФНС исчерпан», шаг 7 со status "error". Бюджет запуска: egr — min(maxPerRun, floor(budgetShare × остаток egr)); search — не больше floor(budgetShare × остаток search). В log: «Ключ принят: egr осталось X, search осталось Y; бюджет на запуск N».

ШАГ 4. UPWARD (сначала). ИНН заказчиков лидов, которых ещё нет в ownership и которые не входят в ИНН групп реестра. Для каждого, пока есть бюджет: WebFetch base/egr?req=<ИНН>&key=<ключ> с просьбой: «Верни дословно поля: ЮЛ.ИНН, НаимСокрЮЛ, Статус, ОснВидДеят.Текст, КолРаб, Контакты (Телефон, e-mail, Сайт), Учредители — для каждого УчрЮЛ.ИНН, УчрЮЛ.НаимСокрЮЛ, Процент; СвОргОсущПр — ИНН и НаимСокрЮЛ. Если юрлицо не найдено — так и напиши.» Учредитель-юрлицо с ИНН из реестра групп — группа найдена. Иначе поднимись к учредителю тем же запросом (к тому, у кого наибольшая доля), не глубже maxDepthUp. Запиши ownership/<ИНН> (set): {inn, name, status, okved, staff, contacts: {phone, email, site}, founders: [{inn, name, share}], chain: [{inn, name, share}] (путь вверх от этой компании до группы или до вершины), group (имя группы из реестра или ""), groupShare (доля на первом шаге цепочки), checkedAt: сегодня, via: "api-fns egr"}. Каждый пройденный уровень цепочки тоже запиши в ownership, чтобы не спрашивать повторно. Не найдено в ЕГРЮЛ (ИП, ликвидировано, пустой ответ) — запиши {inn, name: "", status: статус из ответа или «не найдено в ЕГРЮЛ», checkedAt: сегодня, via: "api-fns egr"}.

ШАГ 5. CANDIDATES (если бюджет остался). Кандидаты из orgdir/group-candidates (поле candidates) по возрастанию rank, у которых нет inn: WebFetch base/search?q=<название без кавычек и организационно-правовой формы>&filter=active+onlyul&key=<ключ>. ИНН бери только при точном совпадении сокращённого наименования, иначе кандидату note «ИНН не определён однозначно». Найден — egr и запись в ownership, как в шаге 4. У кандидата заполни inn, ownerGroup (если цепочка привела в группу реестра), ownerChain, checkedAt; в конце одним update orgdir/group-candidates с if_version (массив candidates целиком; конфликт — перечитай и наложи свои изменения).

ШАГ 6. DOWNWARD (если бюджет остался). Головные компании групп реестра по порядку, начиная с nextGroup: egr по ИНН головной; из «Участия» — организации с долей не меньше minShare (дочки), для каждой egr и её «Участия» с той же долей (внучки). Запиши каждую в ownership (group = эта группа, chain от неё к головной). Группа без ИНН — пропусти. В конце set meta/egrul-state {nextGroup: номер первой необработанной группы по модулю числа групп, updatedAt} с if_version.

ШАГ 7. ИТОГ. update egrul/progress: status "done" или "error", finishedAt, updatedAt, counters, stage — «Готово: запросов egr N, search S; записано организаций M, привязано к группам K, кандидатов с ИНН L; остаток лимита egr R» или текст ошибки. set egrul-runs/<runId>: {runId, startedAt, finishedAt, status, counters, note}. Итоговое сообщение пользователю не нужно.
