# Карточки из «Монитора тендеров РФ»

«Монитор тендеров РФ» (monitor-tenderov-rf.hatchable.site) закрыт входом Hatchable: его API отвечает
`401 login_required`, поэтому облачное задание сбора читать его не может. Карточки оттуда попадают в
монитор-консолидатор через выгрузку JSON (формат `tender-monitor-consolidated-v1`):

- **на сайте** — вкладка «Импорт»: файл распознаётся сам, показывается, сколько отброшено и сколько новых,
  лиды пишутся в `leadsets/imp-…` частями по 200 (код: `mtrfLeads` в `site/monitor.html`);
- **из сеанса Claude** — `mtrf_import.py` по выгрузке базы:

```
python3 mtrf_import.py EXPORT.json W   # W/db/leadsets/*.json — текущие лиды; результат W/out/mtrf-<n>.json
```

Оба пути разбирают выгрузку одинаково (проверено на выгрузке от 26.09.2026: 2 128 карточек, расхождений
в полях нет):

- берутся `datasets.tenders`; отбрасываются категории «Вне профиля…», дубли внутри выгрузки
  (`canonical_tender_id`) и лоты не из РФ (валюта не RUB, регион/источник Казахстан, Таджикистан,
  Узбекистан, Беларусь, домены .kz/.tj/.uz/.by/.kg);
- номер лида — как у наших источников, чтобы одна закупка не показывалась дважды: номер TenderGuru из
  ссылки, номер Бикотендера или РосТендера, номер ЕИС (19 цифр с 0 или 11 с 3), номер B2B-Center,
  id карточки energybase (без приставки, как у источника сбора `energybase`); иначе `mtrf-<номер строки в том мониторе>`;
- уже известные закупки пропускаются по номеру, ссылке и паре «название + срок подачи»;
- `source` — `mtrf:<площадка>` (на сайте «Монитор тендеров РФ · …»), в `note` — категория и fit, которые
  поставил тот монитор.

28.09.2026 загружена выгрузка от 26.09.2026: 2 391 карточка → 1 743 новых лида (185 с открытым приёмом),
385 уже были в базе, 168 вне профиля, 94 не из РФ, 1 дубль. Документы `leadsets/mtrf-20260926-1…9`,
источник `sources/mtrf` (статус «Готов к загрузке»).
