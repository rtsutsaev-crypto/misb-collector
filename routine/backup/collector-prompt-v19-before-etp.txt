ШАГ 0. ПЛАН И СЛОВАРЬ ИЗ БАЗЫ. Прочитай (action "get"):

Работай строго по этим документам: порядок источников, адреса, число страниц, слова и исключения — оттуда.

ШАГ 1. ПРОГРЕСС — ГЛАВНОЕ ТРЕБОВАНИЕ. Сайт показывает документ progress/current в реальном времени. Прочитай его (get) и перезапиши через "set" с if_version прочитанной версии (если документа нет — без if_version):
{runId: "run-ГГГГММДД-ЧЧММ" (UTC), status: "running", startedAt, updatedAt (ISO), percent: 1, stage: «Запуск: читаю план и базу сайта», sources: [все источники из плана: {key, name, method, planned, done: 0, found: 0, fresh: 0, updated: 0, status: "wait" (у type=skip — "skipped"), note: ""}], log: [{at, text: "Облачный сеанс начал сбор по плану v4.6"}]}.
Дальше обновляй progress/current (action "update") после КАЖДОЙ прочитанной страницы или запроса: updatedAt, percent, stage, sources, log (последние 40 записей, новые в конец). Конфликт версии — перечитай и повтори. status источника: wait | reading | ok | partial | failed | skipped. Процент: 5% — чтение базы; 85% делятся поровну между всеми запланированными страницами (percent = 5 + round(85 × прочитано / запланировано)); последние 10% — запись. Записи лога понятные: «РосТендер · Тренинги, RSS: 30 строк, новых 3».

ШАГ 3. ОБХОД ИСТОЧНИКОВ по порядку плана. Перед каждой страницей: status "reading", stage «Читаю <name>, стр. N из M». Отказ на первой странице — остальные страницы источника считай прочитанными (done = planned), status "failed", note с причиной; отказ позже — "partial". Поле pause у источника — пауза в секундах между запросами (sleep). Поле drop_regions — лоты этих стран отбрасывать. Лоты Казахстана, Беларуси, Узбекистана и Кыргызстана НЕ отбрасывать (даже если страна есть в drop_regions): у них country "KZ" | "BY" | "UZ" | "KG", currency "KZT" | "BYN" | "UZS" | "KGS" (цена числом в национальной валюте), law "", region «<страна>, <город или область>». Источники с полем country — иностранные: у их лидов те же поля. У российских лидов country "RU", currency "RUB". Названия могут быть на казахском, кыргызском, узбекском: считай подходящими слова оқыту, біліктілікті арттыру, окутуу, квалификацияны жогорулатуу, o'qitish, malaka oshirish, masofaviy ta'lim, tadbir, konferensiya и их формы. РОТАЦИЯ: если у источника типа api или pages есть поле batch, за запуск обрабатывай только batch элементов списка (requests у api, urls у pages) по кругу. Начало порции — число из документа meta/rotation (get перед первым таким источником, поле cursors.<key>; документа или ключа нет — 0). Порция — batch элементов подряд начиная с этого номера, по кругу (после последнего снова первый). После источника обнови meta/rotation (set с if_version, документа нет — без if_version, конфликт — перечитай): cursors.<key> = (начало + batch) по модулю длины списка, updatedAt, остальные ключи cursors не трогай. planned источника в progress — batch.

Промпт для WebFetch со списками закупок и RSS: «Извлеки все закупки на странице. Каждая строка строго: ID|НАЗВАНИЕ дословно полностью|ЗАКАЗЧИК (организация; пусто, если не показана; никогда не регион)|РЕГИОН|ЦЕНА цифрами в рублях или пусто|СРОК ГГГГ-ММ-ДД или пусто. ID — номер закупки из ссылки или карточки. Закупки РФ, Казахстана, Беларуси, Узбекистана и Кыргызстана; у нероссийских в РЕГИОН пиши «<страна>, <город/область>», ЦЕНА в национальной валюте цифрами с кодом валюты (KZT, BYN, UZS, KGS). Без комментариев.» Строки разбирай сам.

Типы источников:
- pages: читай urls по порядку (RSS-ленты — это XML со списком последних лотов, читай тем же промптом). Лид: url = "https://rostender.info/tender/<id>" для РосТендера, "https://www.bicotender.ru/tender<id>.html" для Бикотендера, ссылка со страницы для остальных или ""; source — из плана; если у источника есть customer, подставь его; если есть verify — добавь поле verify лиду.
- discover: открой страницу from, найди ссылки на разделы из find; найденные прочитай (1 страница каждый), не найденные считай прочитанными с note «раздел не найден». source — соответствующий ключ из поля source. Если у источника есть queries — для каждого слова прочитай первую страницу поиска на найденной странице (поле поиска по наименованию).
- api: к каждому запросу из requests собери URL: base + (path запроса или path источника) + все поля запроса как параметры (кроме law, path и platform; слова кодируй в URL) + common + ключ доступа. Ключи: у источника gosplan (и всех источников с base v2.gosplan.info) параметр apikey=<ключ ГосПлана из задания>; у источников TenderGuru параметр api_code=<ключ TenderGuru из задания>. Слишком длинный URL — убери sort=. Значение {today} в поле запроса замени сегодняшней датой ГГГГ-ММ-ДД. Пауза pause секунд между запросами. Поле deep у источника — глубина: читай у каждого запроса до deep страниц (следующая страница — то же поле skip = 50, 100, …; skip — обычный параметр запроса); у источников закупок остановись раньше, если страница не дала ни одной новой подходящей по словарю закупки, у планов (gosplan-plan44) читай все deep страниц. Ответ, устроенный иначе, чем закупки (планы), разбирай по полю note источника. 429 или ответ о превышении тарифа — остальные запросы источника не делай, считай прочитанными, status "partial" или "failed", note с причиной. 401/403 — note «ключ не принят». Пустой ответ, не-JSON, код 0 или 5xx — повтори тот же запрос до 2 раз с паузой 5 секунд; не получилось и после этого — запрос неудачный, иди дальше, а в note источника напиши сколько запросов не удалось.
  ГосПлан: ответ JSON, проси строки purchase_number|object_info|customer|max_price|срок (collecting_finished_at для 44-ФЗ, submission_close_at для 223-ФЗ)|region. Лид: url "https://zakupki.gov.ru/epz/order/extendedsearch/results.html?searchString=<purchase_number>", customer = "ИНН " + customer, region — название региона по коду (16 → Татарстан республика, 77 → Москва, 78 → Санкт-Петербург, 50 → Московская область и т. д.), price = max_price, source gosplan:fz44 или gosplan:fz223 по law. Если у запроса есть поле purchase_type (источник gosplan-quotes) — это запросы котировок и предложений, прямой спрос: лиду добавь flags ["rfq"] и note «Запрос котировок или предложений». Поля запроса max_price_le и другие фильтры передавай как обычные параметры.
  TenderGuru: ответ JSON со списком тендеров; поля определяй по смыслу названий: номер закупки на площадке (не внутренний ID TenderGuru, если есть оба), название, заказчик, начальная цена, дата окончания подачи заявок, регион, ссылка на карточку. Значение поля вида «Только для подписчиков…» или «Информация доступна только клиентам» — не данные: номером его не считай (бери ID TenderGuru), заказчиком тоже. Лид: id — номер закупки, url — ссылка из ответа или "", source из плана ("tenderguru" или "tenderguru:etp"), law по виду номера. Если у запроса есть поле platform, добавь лиду platform (эта площадка) и note «TenderGuru, фильтр площадки: <platform>»; поля запроса вида e<номер> (e76, e1, e26, e47, e2, e31, e12, e46, e36, e3, e37, e120) — фильтры площадок, передавай как обычные параметры со значением 1. Число страниц запроса — поле pages источника (по умолчанию 1; следующая страница — параметр page=2, 3, …). Тариф может отдавать только 10 карточек на запрос: ответ «access denied» на второй странице — не ошибка ключа, остальные страницы этого источника не запрашивай и напиши в note «тариф не даёт вторую страницу». Только закупки РФ, Казахстана, Беларуси, Узбекистана и Кыргызстана, только приём заявок открыт или закрыт не раньше чем 30 дней назад. Записи, помеченные как «предупреждение о тарифе» или пустые из-за лимита, — источник partial с note из ответа. Источник tenderguru-quotes — прямой спрос (запрос цен, запрос коммерческих предложений, изучение и анализ рынка): каждому лиду добавь flags ["rfq"] и note «Прямой спрос: запрос цен или предложений; запрос «<kwords>»».
  ЭТП РАД (источник rad-lots, без ключа): ответ JSON {count, data: [...]}, до 100 записей на запрос; разбирай скриптом (python). Отбор по словарю — по title.
  Номер, уже известный базе, — не новый лид.
- enrich (TenderGuru, после ГосПлана): собери номера лидов с заказчиком вида «ИНН …» — сначала новые из этого запуска, затем старые из базы, — у которых ИНН ещё нет в коллекции customers (прочитай её в шаге 2: action "list", out_dir). Строки разбирай как у источника tenderguru; отбор по словарю; лиды — source "tenderguru:holdings", customer из ответа. Считай строки и новые лиды по каждому элементу. В конце обнови meta/holdings-stats (set с if_version): {next: (next + batch) по модулю числа terms, updatedAt, terms: {прежние записи + по каждому обработанному q: {group, checkedAt: сегодня, rows, fresh, note: "" или причина ошибки}}}. - discover-api (TenderGuru, разделы «Планы закупок» и «Победители закупок»): открой страницу doc и найди описание раздела section: адрес запроса и параметры поиска по словам. Раздел не описан, страница не открылась или тариф не даёт доступа — status "skipped", note с причиной, запросов наугад не делай.   tg-plans: позиции плана, где срок размещения ещё не наступил, превращай в лиды: id — номер позиции плана (с префиксом "plan-"), title — предмет, customer — заказчик, price, deadline — планируемая дата размещения, source "tenderguru:plans", flags ["plan"], url — ссылка из ответа или "".

Запиши в коллекцию winners, doc_id = ИНН, action "set" (данные прошлых запусков по этому ИНН перезаписываются свежими). found = строк в ответах, fresh = число победителей.
- verify (проверка новых площадок из каталога orgdir): возьми не больше 15 первых элементов targets, которых ещё нет в orgdir/catalog-verify (results) с датой этого дня; если все уже проверены — status "ok", note «все элементы очереди уже проверены». Ничего не выдумывай. Лиды с verify НЕ создавай. Результат по всем элементам запиши одним action "set" в collection "orgdir", doc_id "catalog-verify": {checkedAt: сегодня, runId, results: {<source_key>: {status: "card-ok" | "list-only" | "registration" | "blocked" | "failed", listUrl, cardUrl, cardTitle, cardCustomer, cardDate, note (одной фразой: что увидел, какой доступ)}}}. Перед записью прочитай этот документ (get) и сохрани прежние результаты по ключам, которых нет в этом запуске. found = сколько проверено, fresh = сколько card-ok. Пауза 5 секунд между сайтами.
- egrul (ЕГРЮЛ через API Чекко, ключ <ключ Чекко из задания>): если в тексте запуска ключа Чекко нет или вместо него осталась заглушка в фигурных скобках — status "skipped", note «нет ключа Чекко».
