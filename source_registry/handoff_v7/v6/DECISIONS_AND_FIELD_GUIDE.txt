Пять независимых осей
buying_intent: явный запрос / поиск эксперта / постоянное приглашение / субподряд / гипотеза / справка.
misb_fit: core, adjacent, mixed_scope, uncertain, noncore_consulting. Это тематическая оценка, не наличие исполнителя.
timing: отдельные даты и конфликты; proposal_ready не выводится из будущего дедлайна.
reachability: официальный общий контакт, маршрут площадки, ограниченный доступ или неизвестно.
evidence: полный текст, ограниченный анонс, старая запись без перепроверки, ошибка чтения, общая страница.
Общий балл не используется: хорошая тема не компенсирует закрытый заказ или ложную дату.

не подтверждение заказчика. Прежний контакт сохранен в v5; в текущем слое общий официальный контакт.
FD-N008: тренинг 2 октября против срока площадки 18 октября → срочно уточнить свободный слот.
FD-N021: программа 28 сентября–2 октября → уточнить оставшийся слот, не считать все мероприятие будущим.
FD-N131: бриф до 9 октября и ограничение отклика → доступ и проверка статуса; не брать email-заглушку.
FD-N186: общая регистрация → восстановить доказательство конкретного заказа.
FD-N026: 40 млн ₽ — бюджет всего мероприятия → не включать в возможную выручку МИСБ.
FD-N007: обучение и сопровождение разной аудитории → уточнение объема и экономики.
FD-N132: консультация по сайту → смежная очередь, без удаления.
FD-N001: недоступная карточка + подтвержденный общий контакт РМК → восстановление первоисточника.

Словарь обратной связи
stage: unreviewed / researching / qualified / proposal / negotiating / won / lost / deferred.
loss_reason: topic_mismatch / no_delivery_capacity / closed / access_blocked / duplicate_linked /
budget_mismatch / no_response / not_buying / timing / other.
Дубль помечается связью, а не удалением. no_response требует реально выполненного контакта и даты.
Не заполняй proposal_sent_at, buyer_confirmed, order_won без события и проверяемого основания.

Новый сигнал: обязательный минимум
Уникальный observation_id, исходный URL/ID сообщения, source_id, текстовая выжимка, страна,
дата публикации + основание или null, checked_at, доступ/покрытие, тип сигнала, parent_post_id
для комментария, attachment_url при наличии, язык, наблюдаемые имена/организации, явные сроки.
Гипотезы: отдельные candidate_buyer_ids и match_basis. Ни одна гипотеза не заменяет исходный текст.
Аудио/OCR: отмечай метод и непроверенные фрагменты; числа, даты и контакты проверяй вручную.

Коммерческие маршруты
Прямой заказчик → адресная корпоративная программа после квалификации.
Агентство/организатор → спикер, модуль или субподряд; проверить право заключать договор.
КУ → резерв провайдеров, разработка модулей, следующий учебный цикл.
EdTech/LMS → партнерство только по фактически указанной модели; реселлинг ПО не считать заказом обучения.
Ассоциация → групповой заказ участников либо открытый семинар; спрос участников подтверждать отдельно.

Повторные проверки (предлагаемая частота после запуска)
Запросы с близким сроком: ежедневно; остальные активные запросы: 2–3 раза в неделю.
Пулы партнеров: еженедельно; завершенные программы: по следующему циклу, без выдуманных дат.
Неизвестная дата: отдельная исследовательская очередь; не отбрасывать из-за фильтра 14 дней.
Раз в неделю: недоступные источники, ошибки коннекторов, новые поверхности и источники без находок.
