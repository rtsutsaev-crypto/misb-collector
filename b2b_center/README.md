# Ручная проверка B2B-Center в «Мониторе-консолидаторе МИСБ»

Встраивание прототипа из `prototype/` (исходный README и скрипт) в существующий сайт. Сайт — артефакт claude.ai
(`https://claude.ai/artifact/DXESGRPAkHFVVU8Ugj5PUQ`) с общей базой документов; отдельного сервера у него нет.
Поэтому «серверная задача» — облачное задание Claude Code без расписания, которое кнопка запускает через
`fire_trigger`, как уже работает кнопка «Обновить».

## Как устроено

| Требование README | Как сделано |
|---|---|
| Кнопка «Проверить B2B-Center» в текущем мониторе | Кнопка в шапке и панель «B2B-Center · вкладка «Все»» (`site/monitor.html`) |
| Только нажатие авторизованного пользователя; без cron и автозапуска | Кнопка видна и работает только у владельца сайта (`user.isOwner()` + его коннектор Claude Code Remote). Задание `trig_01TmzSopdvndQ6EGPDQb8eza` создано без расписания. При открытии страницы ничего не запускается |
| CSRF | Неприменимо: у сайта нет своего HTTP-endpoint с cookie-сессией; вызов идёт через среду claude.ai от имени владельца |
| Немедленно вернуть ID задачи | Страница создаёт `runId` (`b2b-ГГГГММДД-ЧЧММСС`), пишет его в `b2b/progress` до вызова и показывает; идентификатор облачного сеанса дописывается в `sessionId` |
| Прогресс: страницы, карточки, новые, обновлённые, ошибка | `b2b/progress` → живая подписка `onSnapshot`; опрашивается только статус уже запущенной задачи |
| Исключить параллельный запуск | Страница: короткая блокировка `acquire` на `b2b/progress` + проверка статуса. Задание: замок по `b2b/progress` с `if_version` и отказ, если идёт другой запуск (свежее 20 минут) |
| Долгий импорт не внутри одного HTTP-запроса | `fire_trigger` возвращается сразу; работа идёт в облачном сеансе |
| Контрольная отметка = начало последнего полностью успешного сканирования | `b2b/state.watermark`; сдвигается только если листание дошло до отметки и прочитаны все обязательные карточки |
| Перекрытие 2 дня, первый запуск 14 дней, глубина в UI | `config/b2b-market` (`overlapDays`, `firstRunDays`); поле «Глубина истории, дней» на панели |
| Предел страниц/время/вёрстка → «охват неполный», старая отметка | `maxPages`, `maxCards`; статус `incomplete`. Сверх README: неполный запуск запоминает прочитанный участок (`b2b/state.resume`), следующее нажатие дочитывает с того места, а не листает всё сначала |
| Вкладка «Все», закрывшиеся тоже; продажи отдельно | `/market/?show=all&from=N`; «Объявление о продаже» пропускается, но учитывается при листании |
| Карточка по каждому номеру; повторная проверка активных | Карточки новых и изменившихся закупок обязательны; повторная проверка активных обязательна для подходящих по темам МИСБ и по остатку лимита для прочих |
| Не отсекать по словам; фильтр института после загрузки | Все закупки хранятся в `b2bmarket/rows-N`; в лиды (`leadsets/b2b-market-N`) идут подходящие по `config/dictionary`; на сайте их дальше оценивает обычный fit |
| Дедупликация `(source, external_id)` и с ЕИС/другими площадками | Ключ записи — номер B2B-Center; лид `b2b-<номер>`. Совпадение по номеру ЕИС из карточки или по паре «название + срок» с лидом другого источника — запись хранится, но второй лид не создаётся (`dupOf`) |
| ИНН только из карточки | ИНН организатора/заказчика берётся, только если напечатан в карточке; дальше сайт сам сопоставляет его с группами и ЕГРЮЛ |
| robots.txt, CAPTCHA/403/вход не обходить | Первым шагом каждого запуска — robots.txt (группы, `*`, `$`, самое длинное правило; агенты `*` и Claude). Запрет → `blocked`, ни одной страницы `/market/` не открывается |
| Ошибка вместо пустого «успеха» | Пустая страница, нарушенный порядок дат, повтор страницы, нет дат, карточка без организатора → ошибка, отметка не сдвигается, собранное сохраняется |

Детерминированная часть (всё, что должно быть точным) — `b2b_core.py`. Облачное задание читает страницы через
WebFetch и вызывает модуль. Код модуля хранится в базе сайта (`config/b2b-core`), а его SHA-256 закреплён в тексте
задания (`routine_b2b_center.txt`): задание не запустит модуль, если код в базе изменён. После правки
`b2b_core.py` нужно заново записать `config/b2b-core` и обновить хеш в задании.

## Файлы

- `b2b_core.py` — ядро: robots, план, листание, карточки, склейка, итог. Только стандартная библиотека.
- `test_b2b_core.py` — тесты: несколько страниц и сбой посередине (отметка не сдвигается, следующий запуск догоняет),
  лимит страниц и дочитывание, перенос срока без дублей, продажи, фильтр института, дубли с ЕИС, лимит и ошибки
  карточек, битые страницы, robots.txt.
- `routine_b2b_center.txt` — текст облачного задания (ключей в нём нет).
- `prototype/` — присланный прототип без изменений.
- `../site/monitor.html` — исходник сайта с кнопкой и панелью.

```bash
cd b2b_center && python3 -m unittest -v test_b2b_core
```

## Что не проверено

Живой smoke-test не проводился: из среды, где выполнялась интеграция, запросы к b2b-center.ru заблокированы, и
обходить блокировку не стали. Первое нажатие кнопки и есть проверка на живой странице. В реестре источников сайта
(`sources/b2b-search`, 24.09.2026) раздел `/market/` уже был отмечен как «поиск запрещён для роботов» — если
robots.txt это подтвердит, запуск завершится статусом «Остановлено» и понадобится официальный API B2B-Center.
Разбор строк списка и карточки идёт через WebFetch (модель пересказывает страницу в заданный формат), поэтому
модуль сверяет число строк с «ВСЕГО» и порядок дат; вёрстку живой страницы никто не смотрел.

Закрытые и приглашённые процедуры и корпоративные площадки группы B2B-Center этим способом не охватываются.
Официальный API B2B-Center (документация в кабинете) — замена источника данных при тех же кнопке, отметке и хранении.
