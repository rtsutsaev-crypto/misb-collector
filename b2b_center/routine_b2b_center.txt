РУЧНАЯ ПРОВЕРКА B2B-CENTER (кнопка «Проверить B2B-Center») для сайта «Монитор-консолидатор МИСБ». Артефакт: https://claude.ai/artifact/DXESGRPAkHFVVU8Ugj5PUQ. Задание запускается только кнопкой, расписания нет. Работай сам, без вопросов пользователю. База сайта — только инструментом ArtifactData (ToolSearch "select:ArtifactData"), url артефакта выше. Страницы B2B-Center читай только через WebFetch; из shell к сайтам не обращайся. robots.txt, капчи, проверки «подождите», 403 и вход по логину не обходи. Ничего не выдумывай: номер, название, организатор, ИНН и даты — только со страницы.

ПАРАМЕТРЫ — в последнем сообщении, JSON от кнопки: runId, lookbackDays (число дней или null), requestedAt, requestedBy. Нет JSON — runId = "b2b-" + UTC сейчас в виде ГГГГММДД-ЧЧММСС, lookbackDays = null. Время всегда бери из `date -u +%FT%TZ`.

Рабочая папка W = /tmp/b2b/<runId>. Контрольную отметку, листание, карточки, склейку и итог считает модуль W/b2b_core.py: `python3 W/b2b_core.py <команда> W ...`. Он печатает JSON; код выхода 3 и {"error": ...} — ошибка, при которой отметка не сдвигается. Решения модуля не переопределяй.

ШАГ 0. МОДУЛЬ. ArtifactData get config/b2b-core с out_dir W/raw; из файла W/raw/config/b2b-core.json возьми поле code и запиши его python-скриптом в W/b2b_core.py байт в байт. `sha256sum W/b2b_core.py` должен быть ровно 852bcf25441d4618e28136f73b2e620451c56691daf85473ec712252d798e47c. Не совпал или документа нет — не запускай модуль, переходи к шагу 8д со status "error" и stage «Ошибка: модуль сбора не прошёл проверку контрольной суммы».

ШАГ 1. ЗАМОК. get b2b/progress (запомни version). Если status "running" или "queued" с другим runId и updatedAt моложе 20 минут — идёт другой запуск: ничего не пиши и заверши работу. Иначе set b2b/progress с if_version: {runId, taskId: runId, sessionId и requestedBy из прочитанного документа (если есть), status "running", requestedAt, startedAt и updatedAt = сейчас, stage «Проверяю robots.txt», params: {lookbackDays}, counters: {pages:0, listed:0, cardsViewed:0, cardsPlanned:0, new:0, updated:0, relevant:0, sales:0, cardErrors:0}, coverage "", log: [{at, text: "Облачный сеанс начал ручную проверку B2B-Center"}]}. Конфликт версии — перечитай и повтори проверку. Дальше после каждой страницы и каждой карточки делай update b2b/progress: updatedAt, stage, counters, log (последние 40 записей, новые в конец).

ШАГ 2. ДАННЫЕ (get/list с out_dir W/raw или W/db): config/b2b-market → скопируй данные в W/config.json; b2b/state → W/state.json ({} если документа нет; запомни version); config/dictionary → W/dictionary.json; list b2bmarket (out_dir W/db, query.limit 1000) и list leadsets (out_dir W/db, query.limit 1000) — модуль читает W/db/b2bmarket/*.json и W/db/leadsets/*.json. W/params.json = {runId, startedAt, lookbackDays}. Из config возьми pause (секунды между запросами к сайту, по умолчанию 3).

ШАГ 3. ROBOTS.TXT. WebFetch https://www.b2b-center.ru/robots.txt с просьбой «Верни содержимое файла дословно, построчно, без пояснений». Запиши текст в W/robots.txt. Статус: 200 — файл получен и в нём есть строки User-agent/Disallow/Allow; 404 — файла нет; иначе фактический код HTTP, а при сетевой ошибке или пересказе вместо файла — 0. `robots W W/robots.txt <статус>`. allowed = false — ни одной страницы /market/ не открывай: шаг 7 с --blocked "<note>".

ШАГ 4. ЛИСТАНИЕ. `plan W` → cutoff, listUrl, pageParam, nextOffset = 0. Страница: URL = listUrl + "&" + pageParam + "=" + nextOffset (и для 0). stage «Листаю вкладку «Все»: стр. N, смещение X». WebFetch с промптом: «Это страница списка процедур B2B-Center (вкладка «Все»). Перечисли ВСЕ строки таблицы процедур по порядку, ничего не пропуская и не объединяя. Каждая строка ответа строго: НОМЕР|ССЫЛКА|НАЗВАНИЕ|ОРГАНИЗАТОР|ДАТА ПУБЛИКАЦИИ|ДАТА ОКОНЧАНИЯ ПОДАЧИ|ПРОДАЖА. НОМЕР — число из ссылки вида tender-<число>; ССЫЛКА — полный адрес карточки; НАЗВАНИЕ — дословно, без типа процедуры и номера; даты — как на странице, ДД.ММ.ГГГГ ЧЧ:ММ; ПРОДАЖА — да для «Объявление о продаже», иначе нет. Последняя строка: ВСЕГО|<число строк процедур на странице>. Без пояснений.» Разбери ответ в W/page-<смещение>.json: [{id, url, title, organizer, published, deadline, sale}]. ВСЕГО не совпало с числом строк — повтори WebFetch один раз; снова не совпало — шаг 7 с --error «список страницы прочитан не полностью». Капча, «подождите», 403, требование входа, пустой ответ — шаг 7 с --error и причиной. `page W <смещение> W/page-<смещение>.json`: next "continue" → следующая страница со смещением nextOffset (note в log, если есть); next "stop" → шаг 5; error → шаг 7 с --error и текстом ошибки. Счётчики pages, listed, sales бери из ответа. Между запросами sleep pause.

ШАГ 5. КАРТОЧКИ. `cards W` → список [{id, url, reason}]; cardsPlanned = его длина. stage «Карточки: N из M». Для каждой WebFetch с промптом: «Это карточка процедуры B2B-Center. Ответь строго одной строкой: ОРГАНИЗАТОР|ИНН ОРГАНИЗАТОРА|ЗАКАЗЧИК|ИНН ЗАКАЗЧИКА|ДАТА ПУБЛИКАЦИИ|ОКОНЧАНИЕ ПОДАЧИ ЗАЯВОК|ДАТА ПОСЛЕДНЕГО РЕДАКТИРОВАНИЯ|СТАТУС|НОМЕР В ЕИС|В АРХИВЕ|НУЖЕН ВХОД|НМЦ. Значения дословно со страницы, чего нет — пусто. Даты ДД.ММ.ГГГГ ЧЧ:ММ. В АРХИВЕ — да, если написано «Процедура находится в архиве». НУЖЕН ВХОД — да, если вместо карточки просят войти или зарегистрироваться. ИНН, номер ЕИС и НМЦ — только цифры. Без пояснений.» Запиши W/card-<id>.json: {organizer, organizerInn, customer, customerInn, published, deadline, edited, status, eis, archived (true/false), loginWall (true/false), price}; сбой WebFetch — {"error": "<текст>"}. ИНН не угадывай по названию: только напечатанный в карточке. `card W <id> W/card-<id>.json`; errorStreak ≥ 3 — прекрати: шаг 7 с --error «карточки не читаются: <последняя ошибка>». Между запросами sleep pause.

ШАГ 6. ИТОГ: `finish W` → W/out/summary.json. Переходи к шагу 8.
ШАГ 7. ИТОГ С ОСТАНОВКОЙ: `finish W --error "<текст>"` или `finish W --blocked "<note>"` → W/out/summary.json. Собранное до сбоя сохраняется, отметка не сдвигается. Переходи к шагу 8.

ШАГ 8. ЗАПИСЬ (только ArtifactData, по порядку):
а) Для каждого имени из summary.writes.b2bmarket — set b2bmarket/<имя> с file_path W/out/b2bmarket/<имя>.json; для summary.writes.leadsets — set leadsets/<имя> с file_path W/out/leadsets/<имя>.json; delete для имён из summary.deletes.b2bmarket и summary.deletes.leadsets. Пачками batch до 50 записей. Другие документы leadsets не трогай.
б) b2b/state: set из W/out/state.json с if_version из шага 2 (документа не было — без if_version). Конфликт — перечитай; если там watermark новее твоего startedAt, не перезаписывай и напиши об этом в log.

д) b2b/progress: update: status = summary.status (done | incomplete | blocked | error), coverage (full → «полный», incomplete → «неполный», иначе ""), counters из summary, cutoff, watermarkBefore, watermarkAfter, finishedAt, updatedAt, запись в log и stage: done — «Готово: новых N, обновлено M, по темам МИСБ K. Охват полный, контрольная отметка сдвинута»; incomplete — «Охват неполный: <note>. Контрольная отметка не сдвинута — нажмите ещё раз, чтобы дочитать»; blocked — «Остановлено: <note>»; error — «Ошибка: <note>. Контрольная отметка не сдвинута».
Если ошибка случилась на шагах 0–2 и модуль ещё не запускался, выполни только д) со status "error".
